## 1. Scope for the MVP
**In:** private **work** Spaces, created by anyone. Joining is by **invite code**, and a Space admin confirms every join with a **Lead / Crew / Viewer** pass. Also in: Teams, Space info and settings, leave, remove, transfer ownership and delete.

**Not in the MVP (hide; don't build):**
- **Community Spaces:** the S3 "What kind of room?" choice, Open or Invite-only communities, Discover, S18 preview and the S15k-A Access sheet.
- **Inviting a person by search** (S16 "Search people on BuildVibes" and Suggested). Pilot crews aren't on BuildVibes yet; the code reaches them on WhatsApp.
- **The tappable invite link** (`buildvibes…/s/…`). It needs the web page, the same as share profile (founder decision: hidden for now). The code works without it.
- **The Work, Chat and Library tabs' content.** These come in weeks 5–6. In week 4, show the tab bar with a simple "coming next" state; this is internal only and never reaches the pilot.

**Words:** "Owners" in the design are the **Space admins**. A Space can have several. "Make admin" adds one. "Transfer ownership" makes someone else an admin and steps you down to member.

## 4. Technical notes
- **Every write is a function call** (`supabase.rpc`). The app has SELECT only on the Spaces tables. Error codes:
  - `42501`: not allowed;
  - `P0001`: a rule, such as "a Space needs an admin" or "already answered";
  - `22023`: bad input;
  - `23505`: duplicate Team name.
  Map each to a plain message.
- **`request_join` and `invite_preview` never raise for a wrong code.** `request_join` returns `status`: `requested`, `pending`, `member`, `declined`, `not_valid` or `too_many_tries`.
- **Joins:** `space_members` has three links to `profiles` (`profile_id`, `confirmed_by`, `removed_by`), and `space_join_requests` has three too. Name the link in embeds, for example `profiles!space_members_profile_id_fkey(...)`, to avoid the "ambiguous" error you hit in task 10.
- **Members who left** stay in `space_members` with `left_at` set (for the record). Filter `left_at is null` in lists.
- **Proof:** confirming a member of a Space linked to a project marks their CV entry for that project as Confirmed, now or when they add it later. The profile proof card (task 10) should now show real "Confirmed" rows. Check it on the emulator.
- **The sign-up invite path** (`invite_code` in the sign-up metadata, which allows any home country) stays on the server for later. In the MVP, code entry is only after sign-in: the pilot team all choose Kuwait.
- **Rights in the app:** read them with `member_rights(space, profile)`. Don't copy the pass presets into Dart.
