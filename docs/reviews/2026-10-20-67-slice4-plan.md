## Server: migration 32 (small)
1. **Received on a Library file.** The file page and the list show who received a file, as faces and names, never a count (rule 3).
   - Receipts stay on file posts. A Library file has no receipts of its own: the faces come from the `received` acks on the posts that carry this file.
   - `library_file_page(file)`: the file, its versions (newest first, the one in use first), who received the version in use, my own Received, and the post to ack through. Readable only by someone who can read the Space (and the Team, for a Team file).
   - `space_library` (or the list read the app uses now) gains, per file: up to 3 receivers' faces, and **new for me** (the newest version replaces an older one and I haven't received it). That is the NEW VERSION tag.
   - No new table. If the build shows one is needed, it gets row-level security and a non-member test, as every table does.
2. **Search leaves out older versions.** `search_space` returns only the version in use of a file. A one-line filter on `supersedes`.
3. **Tests:** a non-member, someone outside the Team and anon read nothing; receivers come only from my Space; search shows Rev D, not Rev C.
4. Same routine as 29–31: an independent check, then a push with the founder's yes, as the only file.

## App, in build order
1. **P1 People.**
   - The request row: quiet, bordered; name, then role, company (plain text unless registered, rule 4) and "wants to join"; **Decline** as text and **Let in** as a pill.
   - Sections **Leads, Crew, Viewers**, in that order. "admin" goes in the role line ("BIM Manager · admin").
   - A pass tag in its colour on the end side: Lead orange, Crew green, Viewer grey. One widget for every pass tag: `BvPassChip` gains a tone; colours come from the tokens.
   - **Teams** as chips after the Viewers, then "+ New team" for the admin only (the server allows only the admin, as in slice 3).
   - At the bottom, **Invite with the code** and its copy button. The code comes from `current_invite`, in the server's format (the frame's "KCT-4821" is a placeholder).
   - The search field and the "Invite people" button go. Who may invite still follows Space info (Only me / Leads / Everyone): a person who may not invite sees no code row.
2. **P2 Let in.** The request row opens in place, with three single-choice rows (rule 6): Lead, Crew, Viewer.
   - **Nothing is chosen first**, as now (S10k-C): letting someone in as a Lead must be a choice, not a default. The frame shows the state after tapping Crew. The pill reads "Let in as Crew" once a pass is chosen.
   - It calls `confirm_join`, and the person moves into their section with a short highlight. No jump to their pass screen.
3. **LV1 Library.**
   - A **Search files** field on top (filters the list in the app).
   - Each row: a stacked-paper thumbnail when there are older versions, the name, "Rev D · 2 older versions · today", a **NEW VERSION** stamp tag when it's new for me, and the faces of who received it on the end side.
   - The All/Files chips and "Recent" go.
   - **No Add file button**, as in the frame. A file reaches the Library through a file post (K4), so everyone gets it, sees it in the daybook and can mark Received. A new version is added from the file's page.
4. **LV2 A file and its versions.**
   - A light page: back arrow, the name, the preview card.
   - Faces and "Received by Islam and Omar", and the **Received** pill (the same `ack` as on the file post).
   - **Versions:** the one in use with an orange dot, "Rev D · in use", who and when; each older one with **Open**.
   - Share in chat and Download go under ⋯ in the header. **Add a new version** sits under the Versions list for the people who may add files. Opening the drawing full screen stays (the dark drawing table, F1).
   - "Used in" stays below the versions.
5. **S Search.**
   - "Search" joins the Space ⋯ menu, above Space info.
   - A full screen: field, ✕ to clear, Cancel. It searches after 2 characters, with a short pause between keys.
   - Groups **Work items** (a checklist point shows under its post), **Files** and **Chat**, each row with its date. A work item shows its stamp (DONE, CHECKED).
   - A row opens the slip in the daybook, the file's page, or the chat thread at that message.
   - No result count (rule 3). Empty: "Nothing found for “…”".
6. **V1 Viewer (small fix).** The bar says "Read only" only for a Viewer. A Crew member whose posting right is locked sees their own pass, not "Crew · Read only".

## Rules to keep
- Arabic for every screen: mirrored, the glossary's words (مسؤول / فريق تنفيذ / مُطّلع, تصريح), Almarai at 16/13, Western digits.
- No counts as quality signals: no member counts, no "3 people received", no result totals. "2 older versions" is a fact about the file, not a quality signal, and stays.
- Every list works with no signal: last read shown, the Received tap waits, then sends.
