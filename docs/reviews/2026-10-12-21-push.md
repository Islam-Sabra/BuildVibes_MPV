## A. Fixes (migration 14 and `supabase/functions/push/`)
1. **A deleted message's text stays in the queue.** After `delete_message`, queue rows still hold the full text, and a late or repeated send would push it.
   - Add a trigger on `messages` (`deleted_at` set) that sets `message_text = null` on that message's queue rows.
   - The function also clears `message_text` when a row is sent.
   - SQL test: deleting a message clears its queued text.
2. **Lost pushes, and a queue that grows forever.**
   - Database webhooks make one attempt. A thrown error leaves the row unsent forever, and FCM 429/5xx is marked sent, so the push is lost.
   - Add `attempts int not null default 0`. On 429/5xx, leave `sent_at` null (honour `Retry-After`).
   - Add `retry_push_queue()`, service role only: rows unsent for over 1 minute, under 1 hour old, with fewer than 5 attempts.
   - `prune_push_queue()` keeps sent rows 1 day, and phones not seen for 60 days are removed.
   - Scheduling both (every minute, and nightly) is a live change: write them as a ready-to-run `cron.schedule` script in `supabase/ops/`, not in the migration.
3. **The function trusts the webhook body.** Read only `record.id`, then claim the row atomically:
   ```ts
   update push_queue set sent_at = now() where id = $1 and sent_at is null returning *
   ```
   - If nothing comes back, answer 200 and stop.
   - Send from the database copy. On a temporary failure, set `sent_at` back to null and `attempts + 1`.
   - This also stops a repeated delivery from sending twice.
4. **Dead-token detection is too broad.** A plain 404 deletes the token, so a wrong `project_id` would wipe every phone after one push.
   - Delete only when the FCM error body says `UNREGISTERED`, or `INVALID_ARGUMENT` about the registration token (optionally `SENDER_ID_MISMATCH`).
   - Everything else counts as temporary.
5. **Webhook secret.**
   - If `PUSH_WEBHOOK_SECRET` is missing or empty, answer 500.
   - Compare SHA-256 digests in constant time.
   - Check `payload.table === 'push_queue'` and `payload.schema === 'public'`.
   - In `supabase/config.toml`, set `[functions.push] verify_jwt = false`. The secret is the guard; the webhook sends no signed-in user.
6. *(Accepted, no change.)* Registering someone else's token string moves it to you, but nobody can read another person's token.
7. **Phones per person:** keep the newest 10 tokens; delete the rest in `register_push_token`. Test it.
8. **Also:**
   - The app re-registers the phone when the app language changes, because the push language comes from the phone's row.
   - Wrap the queue inserts in the triggers in `begin … exception when others then raise warning; end`, so a push problem can never block a post, a message or a work item step.
