## Fixes (inside migration 16)
**M1. A hidden admin still counts as an admin.**
- What goes wrong:
  - a co-admin can leave while the only other admin is hidden;
  - two co-admins can schedule deletion one after the other and leave a Space with no usable admin;
  - `transfer_ownership` and `set_member_admin` can make a hidden person admin.
- Fix:
  - exclude hidden accounts in `has_other_admin`, both subqueries of `account_deletion_blockers`, and `handle_space_admin_gone` (the check and the choice of the next admin);
  - refuse a hidden target in `transfer_ownership` and `set_member_admin(…, true)`;
  - in `request_account_deletion`, lock the person's Spaces (`for update`, ordered by id) before checking blockers.
- Tests: both co-admin cases.

**M2. A hidden account can still write** (post, message, create or sign a work item) as an unnamed "Former member" who can't be blocked. The server must refuse, not only the app.
- One `refuse_hidden_writer()` trigger, BEFORE INSERT, on: `posts`, `post_replies`, `messages`, `follows`, `useful_marks`, `work_items`, `work_item_events`, `library_files`, `space_join_requests`.
  - It raises `42501` "restore your account first" when `auth.uid()` is hidden.
  - The purge runs with no `auth.uid()`, so it isn't affected.
- Add `and not is_hidden_account(auth.uid())` to `is_space_admin()`.
- Tests: one write per table is refused while hidden and works again after restore.

**M3. Purging an admin deletes other members' proof.**
- `cv_project_confirmations.confirmed_by` cascades, and `space_members.confirmed_by` is set null, which `is_space_proof` then rejects.
- That breaks the founder's rule that Space content stays (as "Former member"). Proof on profiles is the MVP's whole point.
- Fix: keep the proof.
  - `cv_project_confirmations`: a surrogate `id` primary key, `confirmed_by` nullable with `on delete set null`, and `unique (cv_project_id, confirmed_by)`.
  - `is_space_proof`: accept a confirmation whose confirmer is gone (null) when the confirmation row exists.
- Test: purge the admin, and the member still shows Confirmed.

**M4. The purge can delete the user while their photos remain.** `max_rows = 1000` cuts the file list. In `purge_account`:
- lock the profile row (`… deletion_scheduled_at < now() - 30 days for update`, else return false);
- return false while any object remains in `avatars` or `post-media` under `<id>/`, so it waits for the next night.

**L1. Restore and purge race.** The lock in M4 fixes it; add a test.

**L2. Purging a reporter deletes their open reports.** Make `reports.reporter_id` nullable with `on delete set null`.

**L4. The export is missing some of the person's own data.** Add:
- their work item comments (their `work_item_events` with a note);
- Library files they uploaded (names and dates);
- blocks, mutes and Useful marks;
- reports they made;
- join requests.

It must still carry nothing written by others.

**Accepted:**
- **(L3)** Follower counts may include a hidden account for at most 30 days.
- **(L5)** The avatar of a hidden person stays reachable by direct link until the purge. The bucket is public, as for blocked people.
