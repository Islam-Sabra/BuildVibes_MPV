## Fixes (inside migration 15)
1. **Removing a chat PDF doesn't remove the document** (high). After `decide_report(remove)` on a message, members still see its Library copy, can download it (`may_read_file` is true), and Home's Today line shows it.
   - Your choice to keep the file for a reversal is right, but it must not stay readable.
   - In the message branch, do what `delete_message` does:
     - set `library_file_id = null`;
     - soft-delete the `library_files` row with `source_message_id = target` (unless a work item uses it);
     - store the old `library_file_id` and the soft-deleted file ids in `removed_content`.
   - On reverse, restore both.
   - Test: after removal, a member can't list or read the file; after reverse, they can.
2. **A reported reply stays in the reporter's Activity with its text.** That's the most common harassment case: an abusive reply on your own post. In `activity_rows`, drop rows whose reply you reported (`reported_by_me('reply', …)`). Test it.
3. **`markets.moderation_email` is readable by anyone, even signed out.**
   - Move it to a service-role-only table `market_moderation (market_id pk → markets, email)`, with row-level security on and no grants.
   - `report_alert()` joins it.
4. **A NULL action counts as a decision.** `decide_report(id, null)` removes, and `decide_appeal(id, null)` upholds. Refuse NULL first in both, and in `block(p, null)`.
5. **A double tap fails on the second report.** Check for a duplicate again after the advisory lock (or `on conflict do nothing` and return the existing id).
6. **`feed_page`, `posts_by` and `posts_tagged` still return posts you reported** (the card is hidden, but pages come back short). Add `not reported_by_me('post', p.id)` next to the block filter.
7. **Home's "replies today" counts a chat reply you reported.** Filter it in `home_day`.
8. **The reporter can still reach the files of a message they reported.** Add `reported_by_me` to the `message_attachments` read policy and to the chat branch of `may_read_file`.

**Also:**
- `orphan_post_media` must not claim photos of a removed post while its appeal is open, or within 14 days of removal. Otherwise a reversed appeal brings the post back without photos.
- *(Accepted)* Removal and appeal results show in Activity without a push.
- The `report-alert` function cancels the Resend response body, and returns 200 on a timeout. The report stays visible in `moderation.sql` query 1, so nothing is lost.
