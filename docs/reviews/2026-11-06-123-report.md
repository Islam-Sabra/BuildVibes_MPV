# Review 123: a sheet's main button always sits above the keyboard: report

**For the lead.** Branch `claude/r123`, off `slice2-app` e3e7c93a (122b merged).
- Not merged.
- Nothing live, no build. No server change.

## What was done
- **The shared sheet (`lib/shared/widgets/bv_sheet.dart`):** a new `BvSheetForm(body:, action:, gap:)`.
  - `body` (the fields) scrolls. `action` (the main button) is a footer at the sheet's foot.
  - The sheet's existing bottom padding already adds the keyboard's height (`viewInsets.bottom`). So with the keyboard up, the footer sits right above it, with the sheet's usual 16 under it.
  - The focused field stays in view through Flutter's own scroll-to-caret, in the same scroll view. The tests check it with the keyboard up.
  - The footer's 1 px `border/subtle` line on top shows **only while the fields run on under it**. It reads the form's own scroll only, so a field that scrolls inside the form doesn't count.
  - The footer sits on the sheet's surface colour.
  - A sheet opts in with `showBvSheet(form: true)`. Why a flag:
    - The sheet's state (the typed text, whether Save is on) lives inside the form, so the button must be built there too.
    - The shared sheet can't see that from outside, and sheets with no field keep scrolling as before.
  - **4 px of the gap above the button scrolls with the fields.** Without it, the scroll edge cut the tails of Arabic letters in the last line above the button (RM1c's error line, 4 px).
- **With the keyboard closed, nothing moves:**
  - each sheet keeps its own gap above the button;
  - all 772 screen goldens pass unchanged.
