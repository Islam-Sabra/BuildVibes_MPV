## What was done
### 1. Projects for any kind of work (P3)
- **Reference data, not code:**
  - `project_kinds`: Building · Infrastructure · Interior · Design study · Software · Website · Plugin or tool · Research · Course · Other. EN/AR names, and a `physical` flag the app will use to offer "where it is".
  - `project_stages`: Design · Tender · Construction · Handover.
  - `market_tools`: the tool list per market (Kuwait and Egypt for now): Revit, AutoCAD, Navisworks, Civil 3D, Tekla Structures, ETABS, SAP2000, Primavera P6, Microsoft Project, Excel, SketchUp, Dynamo. Product names stay in Latin in both languages.
  - All three are readable by signed-in people, with row-level security on.
- **`projects`:**
  - New: `kind_id` (existing projects become buildings) and an optional `stage_id`.
  - Only a building still needs its building type (`type_id`); every other kind may leave it empty. The place stays optional for every kind.
  - `create_project` gains `p_kind_id` and `p_stage_id` with defaults, so today's app call still works (checked through the local REST API).
- **`cv_projects`, new fields:**
  - `what_i_did` (200 characters at most).
  - `status` (in_progress | completed). When it isn't given, it comes from the end month; existing entries were filled the same way.
  - `featured` + `featured_order`: 6 at most per person, each order used once.
  - `with_company_ids`: up to 2 registered companies, a joint venture. They must exist and be on the caller's side of the demo split.
  - `with_company_text`: a typed name, plain text (rule 4). It's one or the other, never both.
  - `link`: one http(s) address.
  - `tool_ids`: from the owner's market list. `tools_text`: up to 5 of their own, 1–40 characters each.
  - `visibility` (everyone | team_only | hidden). Existing entries: shown → everyone, not shown → hidden.
    - **Today's meaning is kept:** `show_on_profile` stays as a mirror, true only for everyone. Setting the old switch still sets everyone or hidden.
    - So the four server functions and the app screens that read it work unchanged until the profile screens move to `visibility`.
- **`cv_project_media`:**
  - Ordered photos and videos; the lowest `sort` is the cover; 10 at most.
  - Stored in the new private bucket `cv-media` (photos and mp4/mov, 25 MB) under `<owner>/<entry>/<file>`, read through signed URLs.
  - **Who can do what:** only the entry's owner adds, reorders or deletes. Readers follow the entry. Storage reads follow the media row, and uploads go only into the caller's own folder.
  - **A Space photo:** only one the caller posted (`post_files.added_by`), and only a photo or a video, recorded in `source_post_file_id`. The app copies the file into the owner's folder when they choose it (rule 8).
- **`cv_project_teammates`:**
  - **Tagging:** the owner tags people, up to 20. Never themselves, never across a block, never an account going away. The owner or the teammate can remove a tag.
  - **Notifications:** each tagged person gets one `cv_teammate` notification, and only one even if tagged again. No confirmation.
  - **Who reads the entry:** `can_read_cv_project` allows the owner; or, never across a block, anyone for everyone, and the tagged teammates for team only.

### 2. Experience with promotions (P2)
`experience_timeline(profile)`:
- returns Experience as the caller may read it (Experience's own visibility applies), newest first, in runs of roles at one company: `[{company_id, company_name, roles: [{id, title, start_month, end_month, promoted_on}]}]`;
- a role is a promotion (`promoted_on` = its start) when the role before it in the run was at the same company;
- a new company starts a new run, with no promotion;
- no new column.

### 3. Finish your profile, from the server
`my_profile_completion()` returns the caller's own `{steps, missing, done, total}`.
- The steps are photo, title (the current title or the headline), current work (a current Experience entry), summary, first project, and the phone number only while the person is in a Space.
- App users only; each person sees only their own.
