**Goal:** 3–5 real people use BuildVibes on their own phones for a week, in one test Space. Everything they hit is fixed before store submission.

## 0b. Lead recommendation: how the pilot installs the app (bare "ok" = accepted)
- **Android.** A new personal Google Play account can't publish publicly until at least 12 testers have stayed in a closed test for 14 days in a row ([Google](https://support.google.com/googleplay/android-developer/answer/14151465?hl=en)). So the pilot team installs from the **closed test**, which needs no public listing.
  - The pilot team counts towards the 12 testers.
  - Public listing waits until after the pilot.
- **iPhone.** The pilot team installs through **TestFlight**, which needs only Apple's lighter beta review.
- **Why:** this takes the December store-review risk off the pilot date.
- **Week 10 changes** from "public submission" to "closed test and TestFlight ready, with the store listing drafted".

## 2. A release build testers can install
- **App id, name and icon:** use what's in the repo now. The new logo comes later and is tracked.
- **Version:** 0.9.0, with build number 1 and going up for every build.
- **Release settings:**
  - no Components screen;
  - no debug banner;
  - only the live project's keys, through `env/prod.json` (git-ignored).
- **Android signing:**
  - Create an upload key. The key file and its passwords never go into git or chat.
  - The founder keeps two copies: one on his PC outside the repo, and one on a USB drive or in a password manager.
  - Losing the key means the app can't be updated in the store.
- **Android delivery this week:** Firebase App Distribution, which is free and needs no Play account. The founder adds tester emails in the Firebase console, and testers get an install email.
- **iPhone:** waits for Apple (§6). Plan the iOS build settings now: bundle id, push capability, the APNs key slot. Don't build until the account is approved.
- **Crash reports:** add Firebase Crashlytics, release builds only.
  - It must never send post text, messages or names.
  - The lead has added it to the Privacy draft under Firebase.

## 3. Test Space and test script
- **The test Space:** the founder creates "Test site" on live, with a project record, as its admin. Testers join with the invite code.
- **Write `docs/test/week9-test-script.md`** in English and Arabic: one page, with a box per task. Each task should take under a minute.
  1. Sign up with the email code, in the tester's own language.
  2. Join "Test site" with the code. The admin confirms.
  3. Create a work item for someone else.
  4. Sign it as done, with a photo.
  5. Check it, or send it back.
  6. Send a chat message and share a drawing.
  7. Post a site update. Mark someone else's post as useful and reply to it.
  8. Turn off one kind of notification.
  9. Report a post, then block and unblock a person.
  10. Optional, on a spare account: delete the account, then restore it.
- **After each task:** "Easy / Hard / Couldn't", plus one line of comment. The founder collects the answers.
- **Lead:** keep the founder's "under a minute" rule (`user-test-plan-v1.md` in the claude.ai project; not in the repo, so §3 is enough).

## 4. Backups (Supabase free plan has none)
- **`supabase/ops/backup.ps1`:** a dump of the live database, schema and data, into a folder **outside the repo** on the founder's PC (for example `D:\BuildVibes backups\YYYY-MM-DD.sql`).
  - Run it weekly, and before every live migration.
  - Never into git, never uploaded anywhere.
  - Photos and files in Storage aren't in the dump. We accept that for the pilot.
- **Practice a restore once into the local database,** to prove the dump works.
- **Pausing:** the free plan pauses a project after one week with no activity. That's no data loss, and it is restored from the dashboard. Mention it in `docs/progress.md` for the gap between the test and the pilot.

## 5. Watching the test

  - members per Space;
  - work items opened and closed per day;

  These are the measures in the MVP plan §5. They're for the founder only and are never shown in the app.
- **Daily during the test week, Claude Code:**

  - lists bugs in `docs/test/week9-findings.md`;
