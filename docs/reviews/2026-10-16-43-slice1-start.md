## How to build it
1. **Components first** (CLAUDE.md):
   - Build the Figma "DS · Daybook components" in `lib/shared/widgets/`, each with a widget test, before any screen.
   - Reuse and restyle the existing BV components where the Daybook redraws them (site tag, stamp, sign-off strip, work item card). Don't keep two versions of the same component.
2. **Retire the 0.9.0 Work tab** (W2–W5 screens) in the same slice, once the Daybook replaces it. Leave no dead code and no second route to the old screens. Live has 0 work items, so nothing needs carrying over; the server alias `not_as_drawing` → `not_as_asked` stays for old app versions.
3. **No signal, basics only:**
   - the app chooses every post's id;
   - a draft survives the app being killed;
   - a post made with no signal waits and sends when the signal is back.
   - The full No signal and Couldn't send screens are slice 10.
4. **Server:** only what migrations 18–19 already provide (`daybook_page`, create, edit, reassign, sign, check, undo, send back, updates, cancel, delete). **If a screen needs something the server doesn't have, stop and tell me.** Don't work around it in the app.
5. **Test data:** a local seed with the prototype's people (Islam, Sara, Omar, Rakesh, Lina, Mona, Yousef) and its posts. Then every screenshot can be compared with its Figma frame line by line. Name it `supabase/dev/seed_daybook.sql`, local only.
