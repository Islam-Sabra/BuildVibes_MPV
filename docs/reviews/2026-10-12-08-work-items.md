### Rules (put them in the server, as in data-model §7)
1. **Steps:** Open → Done (by the owner) → Checked (closed), or Sent back to Open with a reason. Status changes only through functions:
   - `create_work_item`;
   - `sign_done`;
   - `check_item`;
   - `send_back`;
   - `add_comment`;
   - `set_shown_work`.

   `work_item_events` is append-only: nobody can update or delete it.
2. **Who creates:** members with `can(space, 'create_items')`.
3. **The owner** is exactly one active member whose pass allows "mark own items done". A Viewer can't be the owner.
4. **Sign done:** only the owner, only while the item is Open, and with at least a photo or a note. The owner's name and the time are written on the sign-off.
5. **Who checks:** the creator, or a member with `can(space,'check_items')`, which admins have.
   - **Nobody checks an item they own.** If you assigned it to yourself, someone else must check it. Self-checked work is not proof.
   - Check and Send back are only allowed while the item is Done.
6. **Send back:** a reason is required, one of 'photo_missing', 'not_as_drawing', 'not_finished' or 'other'. An optional note; when the reason is 'other', the note is required. The item goes back to Open, into the owner's Needs you.
7. **Reference:** each Space has `ref_prefix`, 2–4 Latin capitals.
   - It's set when the Space is created: Latin initials of the project name if there is one, else of the Space name, else "BV". For example, Kuwait City Tower gives KCT.
   - Numbers run per Space with 3 digits: KCT-001.
   - Add the column and backfill existing Spaces in the same migration.
8. **Reading:** active Space members only. A non-member's select returns nothing.
9. **Needs you** (one function or view per signed-in user):
   - Open items I own;
   - Done items I may check (and don't own);
   - join requests I can confirm.

   Return the Space and item ids so Home (week 7) can reuse it.
10. **Shown work (RE2/RE1):**
    - `set_shown_work(item, bool)` is for the owner of a Checked item only, and everything is hidden by default.
    - `public_shown_work` exposes only: the title, one photo, the place, who checked it and the date, and the project name when the Space is linked.
    - It never exposes the Space name, the discussion or the files.
11. **Evidence photos:** a private storage bucket `space-files`, with the path `<space_id>/<item_id>/<file>`.
    - Members of that Space can read; the uploader writes.
    - Photos shown publicly through shown work get a signed URL from a function that checks `shown = true`.
12. **Tests** (`supabase/tests/07_work_items.test.sql`):
    - each rule above, allowed and refused;
    - the non-member checks;
    - events can't be updated or deleted;
    - a self-check is refused;
    - the public view leaks nothing beyond its fields.
